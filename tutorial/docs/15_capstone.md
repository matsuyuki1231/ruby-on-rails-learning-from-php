## 必須課題: タグ機能（多対多）

プロジェクトに複数のタグを付けられるようにしてください。
1 つのタグは複数のプロジェクトに付きます（例: 「仕事」「趣味」「今月中」）。

### 要件

- タグは名前を持ち、**同じユーザーの中で名前が重複しない**
- プロジェクトの編集画面でタグを付け外しできる
- 一覧でタグが表示される
- タグ名をクリックすると、そのタグの付いたプロジェクトだけに絞り込まれる
- タグを消してもプロジェクトは消えない
- テストを書く（モデルの関連と、絞り込みの統合テスト）

### 設計のヒント（ここまでで学んでいない部分）

多対多は、間に「中間テーブル」を挟みます。

```
projects ──< project_tags >── tags
```

Rails では 2 通りの書き方があります。

```ruby
# ① 中間テーブルをモデルとして持つ（推奨。あとから項目を足せる）
class Project < ApplicationRecord
  has_many :project_tags, dependent: :destroy
  has_many :tags, through: :project_tags
end

class ProjectTag < ApplicationRecord
  belongs_to :project
  belongs_to :tag
end

# ② has_and_belongs_to_many（中間テーブルにモデルを作らない。単純だが拡張しにくい）
```

**①で作ってください。** 実務ではほぼこちらです。

中間テーブルには `[project_id, tag_id]` の複合ユニークインデックスを張ること（同じタグを 2 回付けられないように）。

チェックボックスでタグを選ぶフォームは、次のヘルパーが使えます。

```erb
<%= form.collection_check_boxes :tag_ids, Current.user.tags, :id, :name %>
```

`tag_ids` は `has_many :tags, through:` が自動で用意してくれる属性です。
Strong Parameters では配列として許可します。

```ruby
params.expect(project: [ :name, :description, :due_on, tag_ids: [] ])
```

## 選択課題（1 つ以上選ぶ）

### A. 期限ダッシュボード

トップページ（ログイン時）に、

- 今日が期限のタスク数
- 期限切れのプロジェクト一覧
- 進捗率の平均

を表示する。**N+1 を起こさないこと。**

### B. コメント機能

プロジェクトにコメントを付けられるようにする（1 対多）。
投稿者・投稿日時を表示し、自分のコメントだけ削除できる。

### C. CSV エクスポート

プロジェクト一覧を CSV でダウンロードできるようにする。
（`respond_to do |format|` と `format.csv` を調べること）

### D. タスクの並べ替え

タスクに `position` を持たせ、上下ボタンで順番を入れ替えられるようにする。

### E. プロジェクトの状態管理

`status`（未着手 / 進行中 / 完了）を追加し、`enum` で扱う。
状態でフィルタできるようにする。

## 進め方

手順書はありません。次の順で自分で進めてください。

```
1. 何を作るか紙に書く（テーブル、カラム、URL、画面）
2. マイグレーション → モデル → 関連 → バリデーション
3. rails console で動作確認
4. ルーティング → コントローラ → ビュー
5. ブラウザで確認
6. テストを書く
7. ruby bin/rails test を通す
8. 自己レビュー（下のチェックリスト）
```

**行き詰まったら `/tutorial-hint`。設計に迷ったら Claude に相談してください。**
「A 案と B 案のどちらが良いか、理由つきで」と聞くと学びになります。

## 自己レビューのチェックリスト

コードを見直すときの観点です。

### Ruby として

- [ ] `for` 文を使っていない（`each` / `map` を使う）
- [ ] 不要な `return` を書いていない
- [ ] メソッドが長すぎない（20 行を超えたら分割を検討）
- [ ] 真偽値を返すメソッドに `?` が付いている

### Rails として

- [ ] URL の直書きが無い（パスヘルパーを使っている）
- [ ] ビューに複雑な条件分岐が無い（ヘルパーかモデルに寄せる）
- [ ] コントローラが薄い（DB の絞り込みはモデルの `scope` へ）
- [ ] `Project.find` ではなく `Current.user.projects.find` を使っている
- [ ] N+1 が無い（`log/development.log` を見た）
- [ ] マイグレーションを直接編集していない（適用済みなら新しいマイグレーションを足す）

仕上げに Claude のコマンドを使ってください。

```
/tutorial-review
```

## この先、何を学ぶか

| テーマ | 概要 | 入口 |
| --- | --- | --- |
| Hotwire（Turbo / Stimulus） | ページ全体を再読み込みせずに部分更新する。Rails 標準の SPA 的アプローチ | `bundle add turbo-rails` |
| Active Job | メール送信などを非同期で実行する | `rails generate job` |
| Active Storage | 画像やファイルの添付 | `rails active_storage:install` |
| Action Mailer | メール送信 | `rails generate mailer` |
| API モード | JSON API として使う | `jbuilder`（このアプリに入っています） |
| RSpec | もう 1 つのテストフレームワーク。現場で多い | `rspec-rails` |
| デプロイ | Kamal で本番公開（このアプリに設定ファイルがあります） | `config/deploy.yml` |
| パフォーマンス | インデックス設計、キャッシュ、クエリ解析 | `EXPLAIN`, `bullet` gem |

### おすすめの進み方

1. **Hotwire** … Rails 8 の目玉。このアプリのタスク完了ボタンを非同期化すると効果が実感できます
2. **デプロイ** … 動くものを世に出す経験は大きい
3. **Rails ガイド**（<https://guides.rubyonrails.org/>）を通読
