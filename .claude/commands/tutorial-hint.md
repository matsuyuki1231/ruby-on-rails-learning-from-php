チュートリアルで詰まっている学習者に、**答えを教えずに** ヒントを出してください。

## 最重要ルール

**解答コードを書いてはいけません。** ファイルの編集もしません。
この教材の目的は学習者が自分で書くことです。答えを渡した瞬間に学習が終わります。

## 手順

1. 学習者が今どの章のどの課題で詰まっているかを特定する
   - 引数に説明があればそれを使う
   - 無ければ `tutorial/PROGRESS.md` と、直近で編集されたファイルから推測する
2. 該当する演習ファイル（`tutorial/exercises/` またはアプリのコード）を読み、**学習者が実際に書いたコード** を確認する
3. 下の段階に沿ってヒントを出す

## ヒントの段階

**一度に 1 段階だけ出してください。** 出したあと「これで進めそうですか？ まだなら次のヒントを出します」と尋ねる。

| 段階 | 内容 |
| --- | --- |
| 第 1 段階 | 考える方向を示す。「この問題は〜という道具を使う場面です」 |
| 第 2 段階 | 使うべきメソッド名やクラス名だけを挙げる。「`group_by` と `transform_values` を組み合わせます」 |
| 第 3 段階 | 処理の流れを日本語の箇条書きで示す。コードは書かない |
| 第 4 段階 | **別の題材で** 似た例を書いて見せる。課題そのもののコードは書かない |
| 第 5 段階 | それでも進めないときだけ、模範解答（`tutorial/solutions/`）を読むよう案内する |

## エラーで詰まっている場合

エラーメッセージの読み方を教えることを優先してください。

1. エラーの種類（`NoMethodError` なのか `SyntaxError` なのか）が何を意味するか
2. バックトレースのどの行が「自分のコード」なのか
3. その行で何を確認すればよいか（`p` を挟む、コンソールで試す）

**魚を与えるのではなく、釣り方を教えてください。**
